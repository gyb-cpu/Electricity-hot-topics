# 精选与校准

## 一条资料怎么变成精选

<Steps>
  <Step title="收进来">
    同一网址、同一内容只留一份。没有可信发布时间的资料先不公开。
  </Step>
  <Step title="预筛">
    这是不是本行业的事。宽进，只拦明显无关的。`BLOCK` 不出现在任何公开页面。
  </Step>
  <Step title="评分">
    同一份评分标准独立打两次（0–100）。两次之和 ≥ 2 × 门槛就够分。
  </Step>
  <Step title="结构化">
    分类、标签、主体公司，以及这条资料的事实（谁、做了什么、对什么、什么时候）。
  </Step>
  <Step title="写标题摘要">
    等结构化完成再写。入选的按入选的写法，其余按简短的写法，进「全部动态」。
  </Step>
  <Step title="归组与去重">
    分数够了的资料要等归组完成才进精选：同一件事只出一条由代表报道出面。
  </Step>
  <Step title="成刊">
    日报按规则编排（不调用模型），周报、月报从日报里汇编。
  </Step>
</Steps>

<Info>
  提示词的版本就是它内容的哈希：改了提示词，之后的新资料按新版判断，已经判过的不会重算。
</Info>

## 门槛：`industry/selection.ts`

```ts
export const SELECTION = {
  thresholds: { T1: 60, T1_5: 65, T2: 76 },   // 两次评分的平均至少要到这个数
  understandFloor: 50,                        // 平均分高于它的未入选资料，也按入选的写法写
};
```

官方一手（`T1`）门槛低一些，媒体和个人（`T2`）门槛高一些：同样一件事，官方原文更值得先看。

<Warning>
  这组数是上游示范站在 AI 领域一直在用的门槛，偏严。**换了行业、改了评分标准，一定要重新校准**，不要凭感觉改数字。
</Warning>

## 校准：1. 准备样本

从你自己的信源里挑 100–200 条，一条一条标「该选 / 不该选」，存成 `.data/gold.jsonl`（`.data/` 不进 Git）。`industry/gold.example.jsonl` 有示例。

```json
{"caseId":"law-001","material":{"title":"原文标题","publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"信源名称"},"sourceFacts":{"sourceKind":"rss","sourceTier":"T1","firstParty":true},"gold":{"decision":"select"}}
```

<Note>
  多放**难例**：差一点就该选、差一点就不该选的。一眼就能判断的放太多，准确率会虚高。分出一部分做**留出集**，免得把提示词调成只会做这几道题。
</Note>

## 校准：2. 跑评测

<CodeGroup>

```bash
# 用开发集跑一遍，导入后台 SelectBench
node --env-file=.env scripts/eval-selection.ts \
  --gold .data/gold.jsonl --split development --label "第一版评分标准"

# 最后用留出集检查一遍
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split holdout
```

</CodeGroup>

输出里会同时给：**有效输出准确率 / F1**（模型答出来以后有多准）、**覆盖率**（成功得到决定的样本比例）、**完整准确率**（把失败也算作没做对），以及 40–90 每隔 2 分的门槛扫描。

## 校准：3. 看错例，改标准

在后台 SelectBench 里逐条看判错的资料和模型给的理由：

- 该选没选上 → 评分标准里没说清它为什么重要，把这类价值写进「必须正常评价」的部分
- 不该选却选上了 → 噪声没压住，写进「必须压住」的部分
- 整体偏松或偏紧，而错例分数都贴着门槛 → 再调 `industry/selection.ts`

<Warning>
  **先改标准，再动门槛。** 门槛只能整体移动，解决不了「哪一类判错了」。
</Warning>
